# Threecountry — 천하일지

> **기획 상태:** 게임 구현 전 설계 기준 확정 단계  
> **작업 원칙:** 이 문서 세트가 승인·변경되기 전에는 기능 코드를 늘리지 않는다.

`천하일지`는 후한 말의 군주가 되어 **도시를 다스리고, 인재를 등용하고, 짧고 읽기 쉬운 전투를 통해 나만의 천하를 만드는 모바일 우선 싱글 플레이 웹 전략 게임**이다.

기존 대형 삼국지 게임을 축소 복제하지 않는다. 핵심은 다음 세 가지다.

1. **한 턴은 짧고 선택은 무겁게** — 3~7분 안에 한 계절을 진행한다.
2. **장수는 숫자가 아니라 관계와 이야기** — 능력치, 특성, 충성, 인연, 사건이 함께 움직인다.
3. **역사를 외우는 게임이 아니라 역사를 바꾸는 게임** — 익숙한 인물로 매 판 다른 연대기를 만든다.

## 기준 콘셉트

- 장르: 턴제 군주 운영 + 장수 수집 + 3라인 자동 전투 + 선택형 사건
- 플랫폼: 모바일 우선 웹/PWA, PC 반응형
- 플레이: 싱글 플레이, 오프라인 우선
- 비용 구조: 외부 AI API 없이 동작하는 순수 게임 엔진
- 기본 시나리오: 모든 핵심 장수가 같은 시대에 등장하는 **가상 영웅집결 시나리오**
- MVP 규모: 도시 12개, 세력 7개, 선택 군주 4명, 장수 48명, 사건 60개
- 캠페인: 최대 48턴, 1턴은 한 계절
- 저장: 브라우저 자동 저장, 복수 슬롯은 고도화 단계
- 과금 원칙: MVP 무료, 가챠·행동력·전투 중 광고 없음

## 구현 시작 게이트

다음 조건을 만족한 뒤에만 코드 구현으로 넘어간다.

- 핵심 루프를 한 문장으로 설명할 수 있다.
- MVP에 들어가지 않는 기능이 명확하다.
- 전투 결과가 재현 가능한 규칙으로 정의돼 있다.
- 장수·도시·사건 데이터 스키마가 정해져 있다.
- 같은 시드와 같은 입력은 같은 결과를 만든다.
- 저장 데이터 버전과 마이그레이션 정책이 있다.
- 수직 슬라이스의 완료 기준이 테스트 가능한 문장으로 적혀 있다.

## 첫 구현 목표

처음부터 12개 도시 전체를 만들지 않는다. 첫 코드는 아래 **수직 슬라이스 한 판**만 완성한다.

```text
군주 선택
  → 3개 도시 지도
  → 계절 보고
  → 내정 1회
  → 인재 등용 1회
  → 부대 편성
  → 전투 1회
  → 사건 선택
  → 저장 후 재접속
```

이 흐름이 재미있고 안정적으로 동작한 뒤 콘텐츠를 확장한다.
