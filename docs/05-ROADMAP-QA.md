# 05. 구현 로드맵·QA·출시 기준

## 1. 개발 원칙

1. 화면을 많이 만드는 것보다 **한 턴 전체가 끝나는 것**을 먼저 만든다.
2. 장수·도시 숫자를 늘리기 전에 규칙 엔진을 테스트한다.
3. 새 기능은 코어 명령, 데이터 스키마, UI, 테스트가 함께 있어야 완료다.
4. 밸런스 문제를 UI 애니메이션으로 숨기지 않는다.
5. 플레이어가 이해하지 못하는 패배는 버그에 가깝게 취급한다.
6. MVP 이전에는 온라인·계정·생성형 AI를 붙이지 않는다.

## Phase 2 — 수직 슬라이스

### 범위

- 도시: 허창, 진류, 낙양
- 군주: 조조, 유비
- 장수: 12명
- 도시 행동: 개간, 순찰, 징병, 탐색
- 인재 발견·등용
- 군단 편성
- 병종 3종
- 진형 2종
- 책략 2종
- 전투 1종
- 사건 10개
- 수도 점령 승리

### 완료 조건

한 캠페인이 다음 흐름을 끊김 없이 제공한다.

```text
새 게임
→ 내정
→ 탐색
→ 등용
→ 징병
→ 군단 편성
→ 도시 공격
→ 전투 결과 이해
→ 사건 선택
→ 수도 점령
→ 승리 연대기
```

### 재미 검증 질문

- 다음 턴에 무엇을 해야 할지 스스로 목표가 생기는가?
- 행동점 3개가 답답하기만 하지 않고 고민을 만드는가?
- 장수 하나를 얻었을 때 실제 전략이 바뀌는가?
- 전투 패배 이유를 10초 안에 말할 수 있는가?
- 승리 후 다른 군주로 다시 해보고 싶은가?

두 개 이상이 부정적이면 콘텐츠 확장보다 핵심 루프를 수정한다.

## 3. 테스트 피라미드

### 3.1 단위 테스트

대상:

- 자원 계산
- 도시 수입
- 행동점
- 충성 변화
- 등용 확률 범위
- 병종 상성
- 피해 상·하한
- 책략 성공
- 외교 조약
- 승리 점수
- 난수 재현
- 저장 마이그레이션

### 3.2 속성 기반 테스트

임의 상태를 생성해 항상 지켜야 할 조건을 검사한다.

- 병력·자원 음수 없음
- 피해가 현재 병력보다 클 수 없음
- 같은 장수 중복 배치 없음
- 종료된 조약이 활성 상태로 남지 않음
- 모든 도시는 유효한 소유자를 가짐
- 전투 종료는 최대 라운드 안에 발생
- AI 명령은 검증을 통과함

### 3.3 시뮬레이션 테스트

- AI 대 AI 1,000캠페인
- 각 군주 시작 승률
- 평균 종료 턴
- 도시별 점유 빈도
- 장수별 출전·승률
- 병종별 선택률·승률
- 책략별 사용률·기대 가치
- 자원 파산률
- 조약 파기율

밸런스 경고 예시:

- 특정 군주 승률 65% 초과 또는 25% 미만
- 특정 병종 선택률 60% 초과
- 특정 특성 보유 장수의 승률이 유사 총합보다 15%p 이상 높음
- 캠페인 15% 이상이 48턴까지 사실상 교착
- AI 세력 20% 이상이 10턴 전에 자원 파산

### 3.4 통합 테스트

- 명령 → GameEvent → UI 로그
- 전투 → 도시 점령 → 포로 → 사건
- 턴 종료 → 수입 → 충성 → 자동 저장
- 불가침 조약 → 공격 명령 거부
- 저장 불러오기 → AI 턴 정상 진행

### 3.5 E2E

필수 흐름:

1. 새 게임 생성
2. 군주 선택
3. 개발 행동
4. 장수 탐색·등용
5. 군단 편성
6. 전투
7. 사건 선택
8. 새로고침·이어하기
9. 승리 또는 패배
10. 연대기 확인

## 5. AI QA

### 규칙 준수

- 자원 없이 행동하지 않음
- 조약 위반 시 비용 적용
- 존재하지 않는 경로로 이동하지 않음
- 같은 장수를 중복 배치하지 않음
- 종료된 세력은 행동하지 않음

### 플레이 감각

- 플레이어만 집요하게 공격하지 않음
- 수도가 위험하면 방어함
- 군량이 부족하면 원정을 줄임
- 전력 열세인데 반복 돌격하지 않음
- 동맹 공동 목표에 어느 정도 반응
- 공격 징후를 최소 한 번 노출

### 대기 시간

- Web Worker 오류 시 안전 행동으로 복구
- 제한 시간 초과 시 최고 후보 즉시 선택
- 생각 중 표시가 지도 전체를 가리지 않음

## 6. 밸런스 변경 기록

모든 주요 수치 변경은 다음 형식으로 남긴다.

```text
변경: 기병의 궁병 상성 1.15 → 1.20
근거: 500회 시뮬레이션에서 궁병 방어 진형 상대로 기대 우위가 나타나지 않음
예상 영향: 기병 선택률 상승, 후방 궁병 보호 필요성 증가
회귀 확인: 보병 상대로는 기존보다 강해지지 않는지 검사
```

`감으로 세 보인다`만으로 변경하지 않고 로그·플레이 사례를 함께 남긴다.

## 7. 콘텐츠 QA

### 장수

- 이름 표기 통일
- 출처 유형
- 관계 대상 존재
- 능력치 범위
- 특성 설명과 실제 효과 일치
- 역할 중복 검토
- 기존 작품 전용 표현 미사용

### 사건

- 발생 조건이 영원히 불가능하지 않은가
- 동일 사건이 과도하게 반복되지 않는가
- 선택지 결과가 미리보기와 일치하는가
- 지연 효과가 저장 후에도 실행되는가
- 참여 장수가 사망·포로·타세력일 때 대체 처리가 있는가
- 한 선택이 항상 압도적으로 유리하지 않은가

### 문장

- 모바일 3줄 안에서 핵심 이해
- 불필요한 어려운 한자어 축소
- 역사와 창작 구분
- 맞춤법·호칭 일관성
- 성별·출신을 조롱하는 표현 없음
