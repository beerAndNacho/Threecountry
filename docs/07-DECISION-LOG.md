# 07. 결정 기록과 구현 인계

> 기준일: 2026-08-17  
> 이 문서는 다음 개발 세션에서 같은 결정을 다시 논의하지 않기 위한 기준선이다.

## 1. 확정 결정

### D-001. 제품 형태

- **결정:** 모바일 우선 싱글 플레이 턴제 웹 전략 게임
- **이유:** 짧은 세션, 정적 배포, 서버비 없는 MVP, 기존 프로젝트 운영 방식과 적합
- **영향:** 실시간 PvP·길드·채팅은 제외

### D-002. 핵심 차별점

- **결정:** 대형 삼국지 시뮬레이션의 축소 복제가 아니라 `짧은 턴 + 장수 관계 + 읽히는 자동 전투 + 대체 역사 연대기`
- **이유:** 개발 범위를 통제하면서 독자적인 플레이 경험 확보

### D-003. 기본 시나리오

- **결정:** 역사 연도에 묶이지 않는 가상 영웅집결 `천하각축`
- **이유:** 제갈량·사마의·손견·손권 등 인기 인물을 한 캠페인에 넣으면서 연대 오류를 게임 규칙으로 만들지 않기 위함
- **표시:** 열전에서는 역사·연의·창작을 분리

### D-004. 턴 구조

- **결정:** 1턴은 한 계절, 기본 행동점 3개, 최대 48턴
- **이유:** 한 턴의 선택을 제한하고 모바일 세션을 3~7분으로 유지

### D-005. 지도 규모

- **결정:** MVP 12도시, 수직 슬라이스 3도시
- **이유:** 전략적 연결은 유지하되 콘텐츠·AI·밸런스 폭발 방지

### D-006. 장수 규모

- **결정:** MVP 48명, 수직 슬라이스 12명
- **이유:** 주요 인연과 역할 조합을 제공하면서 개별 대사·특성 품질 유지

### D-007. 플레이 군주

- **결정:** 유비, 조조, 손견, 여포
- **이유:** 인덕·실리·기세·무력이라는 서로 다른 운영 판타지를 명확히 제공

### D-008. 전투

- **결정:** 좌·중·우 3라인, 병종 3종, 진형·책략 선택, 최대 6라운드 자동 전투
- **이유:** 실시간 조작 없이도 편성과 상성을 읽는 재미 확보
- **필수:** 승패 요인 설명

### D-009. 병종 상성

- **결정:** 기병 > 궁병 > 보병 > 기병
- **이유:** 한눈에 이해 가능한 순환 상성
- **주의:** 특정 병종이 언제나 최적이 되지 않도록 지형·진형·장수 적성 반영

### D-010. 장수 시스템

- **결정:** 통솔·무력·지력·정치·매력 5능력치 + 특성 + 충성 + 피로 + 공적 + 관직 + 인연
- **이유:** 기존 숫자를 복제하지 않고 전투·내정·관계를 하나의 모델로 연결

### D-011. 포로 처리

- **결정:** 석방·등용·억류, 처형 제외
- **이유:** 장수 영구 소실과 잔혹한 분위기를 줄이고 캐주얼 전략 톤 유지

### D-012. AI

- **결정:** 외부 AI API가 아닌 규칙 기반 목표·평가 AI
- **이유:** 비용 0원, 오프라인, 결정 재현, 테스트 가능
- **성능:** 계산량이 큰 단계는 Web Worker

### D-013. 기술 스택

- **결정:** TypeScript + React + Vite + 순수 코어 reducer + IndexedDB
- **이유:** 정적 게임에 적합하고 규칙 테스트·PWA·GitHub Pages 배포가 단순

### D-014. 난수

- **결정:** seeded PRNG만 게임 결과에 사용
- **이유:** 같은 입력 재현, 버그 추적, 공유 시드, 자동 테스트

### D-015. 저장

- **결정:** 수직 슬라이스 자동 저장 1개, MVP 자동 1개 + 수동 3개
- **이유:** 초기 구현 단순화 후 캠페인 관리 확장
- **필수:** saveVersion과 마이그레이션

### D-016. 미술

- **결정:** 독자적인 `먹선 미니어처 군웅극`, 3~4등신의 친근하지만 위엄 있는 장수
- **금지:** 기존 게임·드라마 얼굴, 의상, UI, 로고, 음악 복제

### D-017. 수익화

- **결정:** MVP 무료, 가챠·행동력·유료 부활 없음
- **후보:** 추가 시나리오·외형 테마·후원자판

### D-018. 생성형 AI

- **결정:** MVP 미사용
- **이유:** 비용·품질·오프라인·재현성 우선
- **후보:** 출시 이후 선택형 캠페인 회고 문장, 명시적 비용·개인정보 설계 후

## 2. 구현 전 변경 금지 항목

수직 슬라이스가 완성되기 전에는 아래 범위를 늘리지 않는다.

- 도시 3개 초과
- 군주 2명 초과
- 장수 12명 초과
- 사건 10개 초과
- 진형 2개 초과
- 책략 2개 초과
- 온라인 기능
- 계정·클라우드 저장
- 3D·Canvas 대규모 전투
- 역사 시나리오 추가
- 이미지 생성 대량 작업

수직 슬라이스가 재미없을 때 콘텐츠를 더 넣는 것은 해결책으로 인정하지 않는다.

## 4. 주요 위험과 대응

### R-001. 범위 폭발

**위험:** 장수·도시·사건을 먼저 늘려 핵심 루프가 완성되지 않음.

**대응:** 3도시 수직 슬라이스 게이트. README와 로드맵의 범위를 CI 이슈 템플릿에도 반영.

### R-002. 자동 전투가 관전만 하는 게임이 됨

**위험:** 사용자의 결정이 결과에 미치는 영향이 약함.

**대응:** 전투 전 4가지 선택, 3라인 편성, 병종·진형·책략, 1회 전황 선택. 결과 기여도 로그 필수.

### R-003. 전투 공식이 불투명함

**위험:** 사용자가 패배를 운으로 느낌.

**대응:** 난수 폭 0.92~1.08 제한, 승패 요인 3개 표시, 동일 시드 재현 테스트.

### R-004. 유명 장수만 쓰는 최적해

**위험:** 48명 중 일부만 사용.

**대응:** 급여·피로·관직·관계·병종 적성·도시 역할로 분업. 장수별 출전률 자동 시뮬레이션.

### R-005. AI가 플레이어만 공격

**위험:** 불공정한 체감.

**대응:** 모든 세력에 동일한 목표 평가. 공격 이유·국경 집결 징후 표시. AI 대 AI 캠페인 테스트.

### R-006. 모바일 정보 과부하

**위험:** 작은 화면에 수치와 메뉴가 과도함.

**대응:** 지도 중심, 하단 시트, 4개 고정 내비게이션, 상세 수치는 2단계 진입.

### R-007. 저장 데이터 손상

**위험:** 장기 캠페인 이탈.

**대응:** 명령 단위 저장, 버전·마이그레이션, 전투 전후 안전 저장, JSON 내보내기, 원본 보존.

### R-008. 현대 작품과 유사한 표현

**위험:** 독자성·권리 문제.

**대응:** 콘텐츠·아트 바이블, 출처 유형, 자체 능력치 기준, 외부 자산 URL 금지 검사, 현대 대사·이미지 복사 금지.

### R-009. 역사와 창작 혼동

**위험:** 사용자가 가상 설정을 사실로 받아들임.

**대응:** `history / romance / original` 메타데이터와 열전 분리 표시.

### R-010. AI 계산으로 UI 멈춤

**위험:** 모바일 이탈.

**대응:** Web Worker, 시간 예산, 중간 최고 후보, 작은 상태 칩, 지도 전체 오버레이 금지.

## 7. 구현 완료를 주장하기 위한 증거

각 단계 완료 보고에는 다음이 있어야 한다.

- 변경된 기능 목록
- 실행 방법
- 자동 테스트 결과
- 실제 플레이 URL 또는 로컬 경로
- 알려진 제한
- 다음 단계

`코드가 들어갔다`는 완료 기준이 아니다. 사용자가 처음부터 끝까지 해당 흐름을 실행할 수 있어야 한다.

## 8. 변경 관리

핵심 결정 변경 절차:

1. 어떤 문제를 해결하려는지 작성
2. 기존 결정으로 해결할 수 없는 이유
3. 대안 최소 2개
4. MVP 범위와 기술·콘텐츠 영향
5. 문서 수정
6. 테스트 또는 수직 슬라이스 검증

다음 항목은 문서 수정 없이 바꾸지 않는다.

- 핵심 루프
- 행동점
- 전투 구조
- 지도·장수 MVP 규모
- 저장 정책
- 외부 AI 사용 여부
- 수익화 금지 항목
- 독자적 콘텐츠·미술 기준

## 9. 현재 인계 상태

- 저장소는 기획 문서만 존재한다.
- 구현 코드는 아직 시작하지 않았다.
- 다음 작업은 `Phase 1 — 코어 엔진 뼈대`다.
- 첫 공개 플레이 버전의 목표는 전체 MVP가 아니라 3도시 수직 슬라이스다.
- 장수 이미지 대량 제작은 수직 슬라이스 재미 검증 이후다.
